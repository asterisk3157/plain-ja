# コミットメッセージと PR の本文

共通の決まり(SKILL.md の1〜10)に加えて当てます。リポジトリに決まり(AGENTS.md の Commits の節など)があれば、そちらを優先します。

## コミットの題

1. **何が変わったかを常体の1文で**:同僚に言うときの言い方にします。理由は題に入れません。(例:「ユーザー名ではなく GitHub の数値 ID で本人を確かめるようにした」はそのままでよい)
2. **和語の動詞**:足した、外した、直した、まとめた、を使います。追加・修正・対応・整備・改善・強化、体言止め(〜の追加)、「〜しました」は使いません。(例:「ログイン処理の修正」→「ログインが切れる不具合を直した」)
3. **接頭辞はリポジトリの決まりどおり**:`feat:` などは、リポジトリが Conventional Commits と決めているときだけ付けます。

## コミットの本文

4. **困っていたこと → どうしたか**:です・ます で、1〜3文にします。毎回同じ文の型にせず、言い回しは中身に合わせます。
5. **理由を体言止めや「〜ため。」で切らない**:理由は、困っていたことの文として書きます。(例:「ユーザー名は手放すと他人が取れるため。ID を書かなければ、最初のログインで覚える。」→「ユーザー名で確かめていたので、手放した名前を他人が取ると、その人がログインできてしまいました。数値の ID で確かめるようにし、ID を書いていないときは最初のログインで覚えます。」)
6. **長い1文にしない**:「〜を行いました」「〜することで」は使わず、長くなったら2文に分けます。不具合でないものを不具合と書きません。
7. **Markdown を使わない**:本文は改行と空行で区切り、太字は使いません。
8. **「!」は1つまで**:人の役に立つ変更のときだけ、1つまで付けます。docs、refactor、chore には付けません。

## PR の本文

9. **一般的な です・ます と見出し**:見出しは「概要・変更内容・レビューのポイント・テスト」にします。「なぜ」「見てほしいところ」のような砕けた見出し、「〜の第一歩です」のような前置き、「!」は使いません。
10. **太字は要の1文だけ**:レビューのポイントの、いちばん大事な文だけを太字にします。
11. **長い説明は yomiyasu で仕上げる**:概要や変更内容が段落になるときは、yomiyasu で論理のつながりと冗長さを見ます。
