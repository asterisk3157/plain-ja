# スライドの文

スライドの見出し、本文、注釈に当てる決まりです。共通の決まり(SKILL.md の1〜10)に加えて当てます。スライドを組むツールに文の決まり(master-slide-fmt のプロファイルの STYLE.md など)があれば、そちらを優先します。

1. **原案の量を超えない**:ユーザーが原案や箇条書きを出したら、それが完成形の量です。原案の1項目 = スライドの1行にし、説明や理由づけは喋りに回します。書き足したくなった文は、いったん全部消してから要るものだけ戻します。ただし、勉強会や使い方の説明のスライドで、原案が「話す項目」の一覧のときは、読み手が手を動かすのに要るもの(コマンドの例、手順、画面の例、練習のやり方)と、目次・まとめの枚は残します。消すのは、前置き、言い換えの繰り返し、念のための説明だけです。(例:「git commit -m "…"」の例と練習の手順は残し、「→ Git を使うと、これがなくなります」は消す)
2. **常体で書く**:本文も注釈も、体言止めか だ・である で書きます。です・ます は、読み手への依頼だけにします。(例:「見た目が変わっても中身は共通です」→「見た目が変わっても中身は共通」、「指を挟む可能性があります」→「指を挟む可能性がある」)
3. **できない理由ではなく、できる形で**:制約は「この条件ならできる」に言い換えます。(例:「3D プリンタの容量に入らない」→「分割して印刷し、後で接合する」)
4. **比べるものは尺度で**:「難しい」「時間がかかる」で終わらせず、候補を同じ尺度(★5段階、時間、費用)で並べます。読み手に決めてもらう資料には、作った側の推薦の枚を入れません。
5. **都合の悪いことも1行で**:リスクや安全のことは、候補ごとに1行だけ添えます。
6. **1行は全角25字まで**:超えたら削るか、文節で改行します。箇条書きは3〜5個、各1行にします。
7. **かっこで説明しない**:用語の横に、かっこで意味を足しません。(例:「6軸ジャイロ(向きを測る)」→「6軸ジャイロ」)
8. **文で説明しない**:「〜する必要があった」のような説明の文は、名詞の形に縮めます。(例:「USB 有線。接続先を人が手で選ぶ必要があった」→「USB 有線(接続先は手で選択)」、「OpenAI 互換 API で開発者が簡単に統合可能。」→「OpenAI 互換 API(既存のコードのまま)」)
9. **数には条件を付ける**:平均や回数は、何の数かが見て分かるように書きます。(例:「500回の平均」→「乱数を変えて500回試した平均」、あるいは回数を出さずに結果だけを書く)
10. **ひらがなと漢字をそろえる**:同じ語を、ひらがなと漢字で書き分けません。記号や式の書き方(太字、書体)もデッキの中でそろえます。

## 見出しとリード文

AI に書かせると、いちばん崩れやすいところです。

11. **見出しは中身の名前か、言い切り**:その枚に何があるかの名前か、言いたいことの短い言い切りにします。「〜します」「〜しよう」「〜を理解する」のような予告や呼びかけ、「〜とは?」の問いかけ、「〜の重要性」のような中身のない名前にしません。(例:「ブランチ運用を理解しよう」→「ブランチ = 本流から分けて作業する線」、「チーム開発を効率化します」→「1つの作業 = 1つのブランチ」、「コンフリクトとは?」→「コンフリクト」)
12. **リード文は見出しを言い換えない**:見出しの下の1文は、見出しと同じことを別の言葉で言うなら消します。置くなら、その枚でいちばん言いたいことを書きます。(例:見出し「コミット = ある時点の保存」の下の「ファイルの状態を『この時点』として記録する」は消す)

## 中身と形

13. **削りすぎない**:説明の枚には、言いたいこと1つと、それを支える例・図・数・コマンドのどれかを1つ置きます。読み手が判断に使う情報(なぜ困るか、いつ使うか、どれを選ぶか)は、前置きではないので消しません。(例:「よくある失敗」の表の「なぜ困るか」の列は残す。「こんな経験、ありませんか」の前置きの枚は消す)
14. **同じ形を続けない**:表ばかり、箇条書きばかりにせず、中身に合う形を選びます。比べるものは表、順番は番号の手順か流れの図、前と後は左右の対比、確かめることはチェックリスト、操作はコードの例にします。同じ形の表は、デッキの中で続けて使いません。(例:「良いコミットメッセージ」の悪い例・良い例の表と、「よくある失敗」の失敗・対策の表が同じ2列の表なら、前者を左右の対比にする)
15. **表の列名と行名は名詞で**:表の見出しを「なぜ困るか」「どうするか」「なに」のような問いや話し言葉にせず、短い名詞にします。セルの中も、問いに答える話し言葉ではなく、名詞か短い言い切りにします。(例:失敗 | なぜ困るか | どうするか → 失敗 | 困ること | 対策、「なに」「どこで動く」→「役割」「動く場所」、「レビューなしで本流が壊れる」→「レビューを通らない変更が main に入る」、「あとで履歴を読めない」→「履歴から変更の中身が分からない」)
